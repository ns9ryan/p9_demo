# 多语言使用流程

接口字段与请求示例见 [api.md](./api.md)。

`i18n_code` 隔离的是**业务站点/服务**（`platform` / `operator` / `agent`），不是租户 `operator_id`。语言表 `sys_i18n_lang` 全局一份。

## 数据怎么存


| 维度           | 取值                                  | 说明                        |
| ------------ | ----------------------------------- | ------------------------- |
| `i18n_code`  | `platform` / `operator` / `promo` … | 站点。空则当作 `platform`        |
| `i18n_group` | `menu` / `api` / `front` / `login`  | 分组                        |
| `trans_key`  | `menu.route.dashboard`              | 完整 key；写入时短 key 会拼上 group |
| `lang`       | `zh-CN` / `zh-HK` / `en-US` …       | 必须已在 `sys_i18n_lang`      |


唯一约束：`(i18n_code, trans_key, lang)`。

两条翻译通道：

- `i18n.T` **/** `Tf`：进程内 `locale/zh.json`、`locale/en.json`。信封 `msg`、角色名、登录结果等走这里。
- `i18n.TG` **/** `Dict`：查 `sys_i18n`，进程内缓存 2 分钟。菜单标题、接口说明、前端词条走这里。

## 1. 启动：按 PartnerMode 灌词条

`core.yaml`：`PartnerMode=off` → `platform`（18000）。  
`core2.yaml`：`PartnerMode=on` → `operator`（18100）。

```mermaid
flowchart TB
  Start["core-api 启动"]
  Ctx["NewServiceContext<br/>注册 DictLoader → Core RPC"]
  Mode{"PartnerMode == on ?"}
  Op["i18n_code = operator"]
  Pf["i18n_code = platform"]
  Cat["catalog.Register<br/>RegisterCatalog"]
  Lang["幂等写入 sys_i18n_lang<br/>zh-CN / zh-HK / en-US"]
  Menu["upsert 菜单 title=完整 key<br/>如 menu.route.dashboard"]
  Api["upsert 接口 description=完整 key<br/>如 api.userCreate"]
  I18n["按 code upsert 词条<br/>menu / api / front / login"]

  Start --> Ctx --> Mode
  Mode -->|是| Op --> Cat
  Mode -->|否| Pf --> Cat
  Cat --> Lang --> Menu --> Api --> I18n
```



菜单、接口在库里存的是 **key**，不是译文。译文只在 `sys_i18n`。

## 2. 每个请求先定语言

请求头 `X-Lang`。缺省 `zh-CN`。`zh*` → `zh-CN`（`zh-HK` 除外），`en*` → `en-US`，其余原样。

```mermaid
flowchart LR
  H["X-Lang"] --> P["ParseLang"]
  P --> C["ctx 写入 lang"]
  C --> T["T / Tf 用 ctx 语言"]
  C --> G["TG / Dict lang 空时用 ctx 语言"]
```





## 3. 服务端翻译菜单 / 接口

按角色菜单、菜单列表、创建菜单、接口列表、创建接口都会带上当前 API 的站点 code。

```mermaid
flowchart TB
  Req["GET /admin/menu/role 等"]
  Code["CodeByPartnerMode(PartnerMode)"]
  RPC["RPC 返回 key<br/>title / description"]
  TG["i18n.TG(ctx, code, group, key)"]
  Dict["Dict(code, group, lang)"]
  Hit{"缓存命中?"}
  Load["RPC GetI18NDict"]
  Look{"dict 有 group.key 或短 key?"}
  Out["译文"]
  Raw["原样返回 key"]
  Fallback["回退 i18n.T"]

  Req --> Code --> RPC --> TG --> Dict
  Dict --> Hit
  Hit -->|否| Load --> Dict
  Hit -->|是| Look
  Look -->|有| Out
  Look -->|无| Raw
  Dict -.->|loader 为空| Fallback
```



出参约定：

- 按角色菜单：`title` 已是译文。
- 菜单管理：`title` 仍是 key，`trans_title` 是译文。
- 接口管理：`description` 仍是 key，`trans_description` 是译文。

`TG` 查找顺序：`menu.route.dashboard` → 短 key `route.dashboard` → 没有则返回原 key。

## 4. 前端自己拉词条

登录后切语言、渲染公共文案：`GET /admin/i18n/dict`。不进 Casbin。`i18n_code` 必传；`i18n_group` 空则该站点该语言全部组。

```mermaid
flowchart TB
  FE["前端"]
  API["GET /admin/i18n/dict<br/>i18n_code + 可选 group/lang"]
  D["i18n.Dict"]
  RPC["GetI18NDict"]
  DB[("sys_i18n")]
  Map["trans_key → value"]

  FE --> API --> D --> RPC --> DB --> Map --> FE
```



示例：`/admin/i18n/dict?i18n_code=platform&i18n_group=front&lang=zh-CN`

## 5. 后台改词条

语言必须先在 `sys_i18n_lang`。该语言已有词条时，不能改 `lang`、不能删语言。

```mermaid
flowchart TB
  subgraph write [写入]
    C["POST /i18n/create"]
    U["POST /i18n/update"]
    K["POST /i18n/updateByKey"]
    Del["POST /i18n/delete"]
  end

  Norm["normalize：空 code → platform<br/>短 key 拼上 group"]
  Upsert["按 (code, trans_key, lang) 写库"]
  InvC["Invalidate 该 code+group+lang"]
  InvA["InvalidateAll"]

  C --> Norm --> Upsert --> InvC
  U --> Norm --> Upsert --> InvA
  K --> Upsert --> InvA
  Del --> InvA
```



`updateByKey`：`i18n_code` / `i18n_group` 有值才进 WHERE。已有同一 `trans_key` 会按已有站点一起更新；一条都没有则新建（空 code → `platform`，空 group 从 key 第一段推断）。

## 6. 内置 JSON（T）

不进 `sys_i18n`，改代码才变。

```mermaid
flowchart LR
  Ctx["ctx lang"] --> T["i18n.T / Tf"]
  T --> Bundle["locale/zh.json<br/>locale/en.json"]
  Bundle --> Msg["信封 msg / 错误文案<br/>角色名 / 登录结果"]
```
